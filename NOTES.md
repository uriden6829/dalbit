## Architecture decisions (run 1)
- Static web app (PWA), vanilla JS ES modules, **no build step**, in `app/`. Reason: zero dependencies,
  any future Claude session can edit files directly, works offline once installed.
- Hosting/updates: GitHub repo + GitHub Pages via Actions (`.github/workflows/pages.yml`, validates first).
  Her PC opens the URL in Edge and installs it as an app. Every push to `main` updates her copy.
  Progress lives in her browser (IndexedDB); export/import backup in Settings.
- Hash router (`#/home`) + relative paths so it works under `https://<user>.github.io/<repo>/`.
- Service worker: network-first (updates land immediately online), full precache from `app/files.json`
  (generated by `tools/build.mjs`, which also stamps `sw.js` with a content hash).
- Webtoons: own SVG art engine (flat picture-book shapes, paper grain, real Korean signage as reading practice).
  Episodes are data inside each chapter. No AI imagery anywhere → no "AI look".
  Close-ups (zoom > 1) draw in front of counters; staff behind counters are lifted (scene `lift`).
- AI: optional, two modes. (a) her own Anthropic API key, stored only in localStorage (never in backups),
  raw `fetch` from the browser (`anthropic-dangerous-direct-browser-access`), because the app has no bundler for
  the TS SDK. Default model `claude-opus-5-5` (selectable Sonnet 5.5 / Haiku 5.5), server-side refusal fallback
  (`fallbacks: "default"`), web search tool `web_search_20260209` restricted to 15 trusted domains.
  Chat history is resent as plain text only (no thinking blocks replayed → no preserved-thinking prefix issues).
  (b) free Claude.ai "bridge": prompt copied + `claude.ai/new?q=` opened; reply pasted back.
  Both paths go through `validatePack()` (whitelist rebuild + red-flag scan) — one validator.
  NOTE: `claude.ai/new?q=` prefill is believed to work but was not verified; clipboard is the fallback.
- Placement: CAT, 3PL with fixed a=1.4, guess 0.8/n, EAP on a grid, max-info selection rotating skills,
  "I don't know" button. 102 items (Hangul + TOPIK 1–6). Difficulties set by hand from TOPIK level — NOT
  empirically calibrated. Simulation (tools/test/placement-sim.mjs): unbiased, RMSE ≈ 0.35–0.4 logits,
  ~26 items. Tested-out chapters are seeded into review so the SRS verifies them.
- SRS: SM-2 style on study-day indices (4am cutoff). In-session ladder: each new item passes 3–4 different
  exercise types before graduating (≈ 60 exercises for a 10-item lesson).
- Mastery shown as moon phases. Cat is 지지 (Jiji); original design (gold eyes, crescent charm), not the Ghibli one.
  The cat's name is fixed (story text uses 지지; renaming would break Korean particles).
- UI language English (assumed: wife is an English speaker). Korean everywhere in content.
- Family chapter uses 어머님/아버님 and Minji's family (useful if she has Korean in-laws, without assuming it).
- DESIGN.md is written in the user's 개조식 design-doc standard (Korean).
- CLAUDE.md written for future unattended sessions (rules, map, verify steps, publish).

## Task 69 — studio voices (details + build measurements: ../69-study-into-latest-tts-and-ai-voice-engin/NOTES.md)
- Research (Nov 2026): cloud TTS (ElevenLabs v3/v4, Gemini Flash TTS, Typecast…) needs keys/cost/network; big open
  models (VoxCPM2, Qwen3-TTS, Fish S2) need Python+GPU. Chosen: Supertonic 3 (Supertone, 2026-04, ONNX, 10 voices,
  OpenRAIL-M), run in Node at BUILD time → every course line pre-rendered to Ogg Opus in app/voice/.
- app/js/lib/voicecast.js = casting + clip names (shared by app and builder). speech.js plays clips first, browser
  voice for anything uncovered or if a clip fails. Settings → Voice: Studio / Browser. settings.voiceEngine.
- Builder tools/voice/ (only npm deps in repo, dev-only): corpus → number reading → render (slow = phrase-chunked)
  → trim/level → Whisper check + retakes → Opus via headless Edge WebCodecs + own Ogg muxer → manifest.
- sw.js: clips cache-first in 'voice-clips-1' (survives updates); build.mjs does not precache clips.
- Tests: tools/test/voice-play.mjs (headless: clip / slow clip / fallback / browser setting).
